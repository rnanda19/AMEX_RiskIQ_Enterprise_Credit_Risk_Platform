# Contributing / Development Standards

This is a solo portfolio project (not accepting external PRs at this time),
but it follows real engineering discipline so the practices themselves are
demonstrable. This document is that discipline, written down.

## Standing rules (apply to every notebook and every module)

- **Zero-fabrication**: every displayed value is computed live by that
  notebook's own code during that run. Anything the dataset has no ground
  truth for (e.g. business financial assumptions) is an explicit, labeled,
  editable `ASSUMPTION` — never silently presented as fact.
- **One markdown intro cell + one consolidated code cell** per notebook.
  Every output file is written to a fixed path, overwritten in place
  (idempotent re-runs).
- **WARP hardware standard**: 95% of detected logical CPU cores, 90% of
  detected RAM as a planning ceiling, read from
  `artifacts/project_config.json`'s `resource_limits` block (see
  `shared/config.py`). `random_state` / `RANDOM_SEED = 42` everywhere.
- **No absolute/local file paths printed** in any notebook output — these
  notebooks get shared publicly.

## Code organization

- `shared/` — logic used by more than one notebook or service, extracted
  from wherever it was first written, tested independently. See
  `shared/__init__.py` for the extraction policy (existing notebooks keep
  their own inline copy until each is deliberately migrated — see
  `ROADMAP.md`).
- `ProblemN_.../src/` — standalone services generated by that problem's
  notebooks (the FastAPI app, the Docker files, the monitoring job). These
  are already real Python modules, not notebook cells, so they're testable
  as-is.
- `ProblemN_.../tests/` — pytest tests for that problem's `src/`. See
  `01_Problem1_Credit_Scoring_PD_Prediction/tests/conftest.py` for the pattern
  used to test a service that needs config/model artifacts without
  requiring the real (multi-GB) trained files in CI.

## Before committing

```bash
pip install -r requirements-dev.txt
python -m pytest shared/tests ProblemN_.../tests -v
python scripts/check_notebook_syntax.py .
pyflakes shared/ scripts/ ProblemN_.../src ProblemN_.../tests
```

All four run in CI on every push to `main` (see `.github/workflows/ci.yml`).
Lint is currently advisory (`continue-on-error: true`) — see `ROADMAP.md`
for making it blocking once the existing notebook-generated `src/` files
are swept for the same class of unused-import findings this already
surfaced (see `docs/known_lint_findings.md`).

## What NOT to do

- Don't change a notebook's actual computed output (a number, a chart, a
  model artifact) as a side effect of an infra/tooling change. If a change
  could affect output, re-run the notebook and re-verify before committing
  — this repo's whole value is that every number in it is real.
- Don't add a dependency to `requirements-dev.txt` that a notebook itself
  needs — that belongs in the relevant `ProblemN_.../requirements.txt`
  instead. `requirements-dev.txt` is CI/testing-only.
